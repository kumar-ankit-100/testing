# E4-S2: Pro-rata billing calculation service

**Epic:** E4 — Plan Upgrade/Downgrade with Pro-Rata Billing
**Layer:** Service
**Group:** C
**Depends on:** E4-S1

## Description

Pure calculation service implementing the AC-05 pro-rata formula for upgrade/downgrade, using Decimal arithmetic exclusively, including correct handling of leap-year month boundaries.

## Acceptance Criteria

1. A plan change exactly at a billing-cycle boundary produces a pro-rata charge of 0.00 for the boundary day attribution per the documented formula.
2. A plan change mid-cycle in a 28-day February (non-leap year) and in a 29-day February (leap year, e.g., 2028) both produce correct, independently-asserted pro-rata amounts using the actual days-in-month for that year.
3. The calculated charges_total is always >= 0 for every generated test case (NFR-08 invariant), including a downgrade scenario that could naively produce a negative credit-only figure.
4. All intermediate and final amounts are Decimal typed; a static/type check confirms no float is used in the calculation module.
5. A unit test table-drives at least 6 boundary-date scenarios including the leap-year case and asserts exact expected Decimal values.
