# E6-S5: CSR/Admin subscription termination service

**Epic:** E6 — CSR Exception Queue & Overrides
**Layer:** Service
**Group:** F
**Depends on:** E5-S2

## Description

Service allowing a CSR or admin to close a subscription outright (`ACTIVE`/`SUSPENDED` → `TERMINATED`) via the shared FSM (AC-02), independent of the port-out flow. This closes the gap identified in `system-design.md` §5.1: `TERMINATED` is a reachable enum value (E1-S1) and a required input to churn reporting (E7-S1), but no earlier story defined a trigger for it. Every termination — successful or rejected — is written to the append-only `StateTransition` log with actor, timestamp, and a mandatory reason code, giving it the same audit character as a CSR override (AC-09) even though it does not use the `CSROverride` table (it is not overriding a prior rejection).

## Acceptance Criteria

1. A CSR or admin can terminate a subscription in state `ACTIVE` or `SUSPENDED`, supplying a mandatory reason code; the subscription transitions to `TERMINATED` via the shared FSM transition table (AC-02).
2. Terminating a subscription in any other state (`PENDING_KYC`, `PORT_OUT_REQUESTED`, `PORTED_OUT`, `TERMINATED`) raises `InvalidSubscriberStateException` and writes no `StateTransition` row (AC-02).
3. Attempting termination without a reason code is rejected before any state change or `StateTransition` row is written.
4. A non-CSR/non-admin principal (subscriber or dealer-context) attempting termination is rejected.
5. Every termination that reaches the persistence step — successful or not — writes a `StateTransition` row with a non-null `actor`, a non-null `reason_code`, and a timestamp, before returning (AC-09-style audit trail), and logs a structured entry with the masked actor.
