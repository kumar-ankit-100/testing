# E2-S3: Rule-based activation engine (KYC, dealer, MNP)

**Epic:** E2 — Subscriber Registration & Rule-Based Activation
**Layer:** Service
**Group:** D
**Depends on:** E2-S2

## Description

Service that evaluates the stubbed KYC flag, dealer code (against DealerMaster, DEALER-FAIL sentinel), and MNP flag to transition a subscription from PENDING_KYC to ACTIVE via the FSM, or reject with a specific, independently-testable failure reason per AC-08.

## Acceptance Criteria

1. Activation with KYC-verified flag, a valid dealer code, and MNP-success flag transitions the subscription to ACTIVE and appends a StateTransition record.
2. Activation with an unverified KYC flag is rejected with reason code KYC_UNVERIFIED and the subscription remains PENDING_KYC.
3. Activation with dealer code DEALER-FAIL is rejected with reason code DEALER_INVALID and the subscription remains PENDING_KYC.
4. Activation with the MNP-fail flag is rejected with reason code MNP_FAILED and the subscription remains PENDING_KYC.
5. Attempting to activate a subscription that is not in PENDING_KYC (e.g., already ACTIVE) raises InvalidSubscriberStateException.
6. A test attempts to activate two registrations for the same mobile number concurrently/sequentially and asserts only one reaches ACTIVE (double-activation race, NFR-07).
