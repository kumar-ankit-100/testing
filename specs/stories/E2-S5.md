# E2-S5: Subscriber self-registration and activation status UI

**Epic:** E2 — Subscriber Registration & Rule-Based Activation
**Layer:** UI
**Group:** F
**Depends on:** E2-S4, E1-S6

## Description

Responsive React screen where a subscriber submits registration details and sees activation status/rejection reason, satisfying the responsive-layout rubric item. Also owns the frontend side of the `E1-S6` auth fix: a login page and a role-based route guard, since no story previously covered how the frontend obtains or attaches a token.

## Acceptance Criteria

1. Registration form collects mobile number, identity-proof reference, and plan type, and submits to the registration endpoint.
2. On activation failure, the UI displays the specific reason code/message returned by the API (e.g., 'KYC not verified').
3. On activation success, the UI displays state ACTIVE.
4. The layout renders correctly (no horizontal overflow, controls usable) at both a 375px mobile viewport and a 1280px desktop viewport, verified by a Playwright test.
5. A login page calls `POST /api/auth/login` (per `E1-S6`) and stores the returned token; registration/activation calls attach it as a bearer token rather than calling the API unauthenticated.
6. A role-based route guard redirects to the login page when no valid token is present, and blocks rendering a route scoped to a role the current token doesn't carry.
