# E1-S4: Role-based auth and controller-level authorization

**Epic:** E1 — Platform Foundations
**Layer:** API
**Group:** B
**Depends on:** E1-S1, E1-S2

## Description

Auth dependency-injection layer enforcing roles (subscriber, CSR, admin, dealer-context-only) at the API controller level, and enforcing that subscribers may only access their own subscription data (NFR-04).

## Acceptance Criteria

1. Every non-health API route requires an authenticated principal with a role; unauthenticated requests receive HTTP 401.
2. A subscriber-role request to a CSR-only or admin-only endpoint receives HTTP 403.
3. A subscriber requesting another subscriber's subscription data (by ID mismatch) receives HTTP 403.
4. A CSR or admin principal can access endpoints scoped to their own role without a 403.
5. An integration test exercises all four cases above against a running test client.
