# E4-S1: Billing record repository (append-only)

**Epic:** E4 — Plan Upgrade/Downgrade with Pro-Rata Billing
**Layer:** Repository
**Group:** B
**Depends on:** E1-S1, E1-S2

## Description

Append-only persistence for BillingRecord entries generated by plan changes, storing all monetary fields as Decimal-backed columns.

## Acceptance Criteria

1. Repository exposes create_billing_record and list_billing_records_for_subscription; no update_billing_record or delete_billing_record function exists.
2. Monetary columns are stored and retrieved as Decimal, never float, verified by a unit test comparing exact Decimal equality after round-trip.
3. Attempting to run a raw UPDATE or DELETE against the billing_records table (e.g., via a direct SQL statement in a test) either fails via a DB constraint/trigger or is asserted absent from the codebase.
4. A unit test creates two billing records for the same subscription and asserts both remain retrievable (no overwrite).
