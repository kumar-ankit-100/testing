# E2-S4: Registration and activation API endpoints

**Epic:** E2 — Subscriber Registration & Rule-Based Activation
**Layer:** API
**Group:** E
**Depends on:** E2-S3

## Description

REST endpoints exposing registration and activation, mapping service outcomes to appropriate HTTP status codes and reason codes.

## Acceptance Criteria

1. POST /api/subscribers/register with valid input returns HTTP 201 with the new subscriber ID and state PENDING_KYC.
2. POST /api/subscribers/{id}/activate with all stub flags passing returns HTTP 200 with state ACTIVE.
3. POST /api/subscribers/{id}/activate with a failing stub flag returns HTTP 422 with a machine-readable reason code (KYC_UNVERIFIED, DEALER_INVALID, or MNP_FAILED).
4. POST /api/subscribers/{id}/activate on an already-ACTIVE subscriber returns HTTP 409.
5. All requests/responses are validated against typed request/response models (no untyped dicts).
