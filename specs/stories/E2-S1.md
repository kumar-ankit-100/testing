# E2-S1: Subscriber repository and seeded dealer master

**Epic:** E2 — Subscriber Registration & Rule-Based Activation
**Layer:** Repository
**Group:** B
**Depends on:** E1-S1, E1-S2

## Description

Persistence layer for Subscriber/Subscription records plus a seeded DealerMaster table used to validate dealer codes at activation time (no dealer-facing UI).

## Acceptance Criteria

1. Repository exposes create_subscriber, get_subscriber_by_id, and get_subscriber_by_mobile functions backed by SQLite.
2. A partial unique index exists on (mobile_number) restricted to state=ACTIVE, enforcing at most one ACTIVE subscription per mobile number at the database level.
3. DealerMaster table is seeded with at least 5 valid dealer codes plus the DEALER-FAIL sentinel code on application startup/migration.
4. A unit test inserts two subscriptions with the same mobile number both attempting ACTIVE state and asserts the second raises a database integrity error.
5. Repository module imports only from Types and Config.
